# lecture-recognition

Локальная транскрибация лекций в SRT: выбирается человек с наибольшим
суммарным временем речи. Остальные самостоятельные реплики исключаются.

Пайплайн: FFmpeg → NVIDIA Nemotron 3 Diarization → Qwen3-ASR 1.7B →
Qwen3 ForcedAligner 0.6B → SRT. Русский язык используется по умолчанию.
Пересказ и литературная правка текста не выполняются.

Будущие эксперименты с новыми ASR и дообучением под лектора:
[инструкция для Codex на другой машине](docs/experiments-handoff.md) и
[последовательность экспериментов](docs/experiments-roadmap.md).

## Установка (Windows / PowerShell)

Требуются NVIDIA GPU, актуальный драйвер, FFmpeg в `PATH` и
[uv](https://docs.astral.sh/uv/). Отдельно устанавливать CUDA Toolkit не нужно:
CUDA runtime входит в закреплённую сборку PyTorch. Проект использует Python 3.12.

```powershell
uv sync --locked
uv run python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name())"
```

Первый запуск скачивает три модели Hugging Face. Далее веса остаются в
стандартном HF-кэше. Аудиозаписи обрабатываются локально.

## Запуск

```powershell
uv run lecture-recognition record\20260925_101716.m4a
uv run lecture-recognition "record\другая запись.mp3" --output record\lecture.srt --language ru
uv run lecture-recognition record\20260925_101716.m4a --batch-size 8
uv run lecture-recognition record\20260925_101716.m4a --chunk-seconds 120 --min-chunk-seconds 60 --batch-size 2 --output record\20260925_101716.srt
```

Поддерживаются аудиоформаты, декодируемые установленным FFmpeg, включая
M4A/AAC, WAV, MP3, FLAC. По умолчанию SRT сохраняется рядом с аудио.
Существующий SRT по выбранному пути заменяется только после успешной обработки.
Таймкоды относятся к исходной записи: вырезанные студенческие реплики не сдвигают время.

Быстрая проверка первых 65 секунд:

```powershell
uv run lecture-recognition record\20260925_101716.m4a --limit-seconds 65 --output record\smoke.srt
```

`--language` принимает `ru`, `en`, `zh`, `yue`, `fr`, `de`, `it`, `pt`, `es`.
Этот список ограничен поддержкой выравнивания и установленными токенизаторами.
При использовании `--limit-seconds` без `--output` результат получает суффикс
`.preview.srt`, чтобы не заменить полные субтитры пробным фрагментом.

## Длинные записи и память

- Модели работают на CUDA по очереди; Qwen в BF16. По умолчанию ASR обрабатывает
  один фрагмент, `--batch-size` увеличивает пакет для лучшей загрузки GPU.
  При нехватке памяти пакет повторяется по одному фрагменту.
- Звук декодируется один раз в дисковый mono PCM 16 кГц (~230 МБ/час).
- Nemotron сохраняет speaker cache между чанками. Идентификаторы спикеров
  не сбрасываются на границах; лектор выбирается после прохода всей записи.
- ASR получает фрагменты до 120 секунд по умолчанию (`--chunk-seconds`), включая
  перекрытия. Минимум основной части — строго 60 секунд (`--min-chunk-seconds`).
  Отдельные реплики студентов заменяются нулями той же длительности в отдельном
  PCM-кэше; ASR и aligner используют это аудио. Одновременная речь с лектором сохраняется.
  Паузы остаются внутри фрагментов, исходные таймкоды не сдвигаются.
  Короткий хвост перераспределяется; если разбиение невозможно, в конец добавляется
  минимально необходимая тишина. Искусственное время не попадает в SRT.
  Чанки без речи лектора пропускаются.
  Нарезка выполняется с поиском тихой границы и контекстом
  до секунды с каждой стороны. Минимум и максимум должны оставлять место для перекрытий.
- ForcedAligner привязывает слова ко времени. Перекрытия обрабатываются на
  уровне слов; субтитры группируются по паузам и пунктуации, до двух строк.
- При нехватке CUDA-памяти пакет повторяется по одному чанку. При нехватке памяти
  или достижении лимита генерации отдельный чанк делится только при сохранении
  минимальной длины обеих частей, иначе запуск завершается с ошибкой и сохранённым кэшем.
  Неуспешное выравнивание завершает запуск с ошибкой.
  Для коротких реплик с нулевой длительностью выравнивание сначала повторяется
  с 250, 500 и 1000 мс тишины вокруг аудио; добавленное время вычитается из
  меток. Если измеренного интервала по-прежнему нет, точные метки не выдумываются.
  При сбое на границе чанка aligner повторяет выравнивание с дополнительными
  двумя секундами соседнего маскированного аудио с каждой стороны.
  Границы владения словами сохраняются для удаления дублей. Если повтор тоже
  неудачен, запуск завершается с ошибкой; завершённые ASR-чанки остаются в кэше.

В `.lecture-cache/` хранятся PCM, закреплённые ревизии моделей, завершённая
диаризация и результаты отдельных ASR/aligner-чанков. Повторите ту же команду,
чтобы продолжить работу. Прерванная диаризация повторяется целиком: её внутреннее
состояние между запусками не сериализуется. Настройки, версия алгоритма,
версии библиотек, хэш содержимого и длительность учитываются в ключах кэша.
Размер пакета тоже учитывается: возобновляйте запуск с тем же `--batch-size`.
Минимум и максимум чанков и версия маскирования также входят в ключ кэша.
После перехода на маскирование старые ASR/aligner-результаты не используются;
первая обработка с новыми настройками выполняется заново.
Путь можно изменить через `--cache-dir`.

Содержимое `record/` и `.lecture-cache/` исключено из Git, кроме
[ручной разметки 20260925_101716.review.md](record/20260925_101716.review.md).
Этот файл хранится вместе с исходниками; агент должен прочитать заполненные
карточки перед подготовкой эталонов для экспериментов. Аудио, SRT и кэш
переносятся отдельно. Технические JSON находятся только в кэше;
пользовательский результат — SRT.

## Ограничения качества

Nemotron размечает активность максимум восьми спикеров, но не разделяет
смешанное аудио на голоса. Участки, где одновременно говорят лектор и студент,
сохраняются: слова студента на них иногда могут попасть в субтитры.
Результат также зависит от качества диаризации и записи. Человек с наибольшим
временем речи считается лектором даже при отсутствии большинства свыше 50%.

Тихие реплики, наложения и границы фраз требуют проверки прослушиванием.
Forced alignment оценивает время уже распознанного текста и не доказывает
правильность распознавания.

## Проверки

```powershell
uv run pytest -q
uv run ruff check src tests scripts
uv run python scripts\check_diarization.py record\20260925_101716.m4a
uv run python scripts\prepare_review.py record\20260925_101716.m4a
```

`check_diarization.py` использует CUDA и сравнивает штатный offline-проход с
подачей чанков на коротких фрагментах реального аудио. Обычные тесты не
скачивают веса и не требуют GPU.

`prepare_review.py` после завершения транскрибации создаёт в кэше короткие
WAV-фрагменты начала, середины, конца, стыков чанков и реплик других спикеров.
В `manifest.json` записаны исходные таймкоды для проверки прослушиванием.
Эти фрагменты сами по себе не являются проверенной эталонной расшифровкой.

### Проверено на тестовой лекции

На Windows, RTX 4060 Laptop 8 ГБ, с `--batch-size 8` обработана вся запись
`record/20260925_101716.m4a` (5329,92 секунды). Получено 1386 блоков SRT.
Проверены последовательность таймкодов, отсутствие пересечений, длительность
до 7 секунд и принадлежность выбранным интервалам лектора.

Диаризация заняла 27,6 с (пик 0,40 ГБ), ASR — 264,2 с (пик 5,49 ГБ).
Это измерения этапов с уже скачанными весами, включая их загрузку.
Выравнивание завершено с проверенным восстановлением после остановки на
короткой реплике. Отдельная CUDA-проверка подачи Nemotron чанками на 5,37,
30,4 и 61,37 секунды не выявила расхождений в активности спикеров относительно
штатного offline-прохода. Проходят 24 автоматических теста.

Точность слов (WER) не измерялась: проверенной эталонной расшифровки нет.
Контрольные WAV-фрагменты подготовлены для прослушивания, но ручная вычитка
всей лекции не выполнена.

Источники: [Nemotron](https://huggingface.co/nvidia/Nemotron-3-Diarization),
[Qwen ASR и ForcedAligner](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf),
[Transformers diarization API](https://huggingface.co/docs/transformers/main/model_doc/nemotron3_diarization).

Эксперимент с длинными ASR-входами: [измерения памяти, скорости и сравнение нарезки](docs/asr-chunk-benchmark.md).

### Перебор предобработки

```powershell
uv run python scripts/benchmark_preprocessing.py "record\20260925_101716.m4a"
```

Скрипт использует диаризацию и границы чанков завершённого рабочего запуска,
проверяет первые 300 секунд и ищет точное слово «квазистационарности» в 02:25–02:35.
Слово служит только критерием проверки и не передаётся модели в подсказке.
Проверяются контекст, левый/правый каналы, нормализация, частотные фильтры,
шумоподавление и компрессия. Основная часть чанка не короче 60 секунд.
Первые попадания проверяются со сдвигами ±5 секунд и на полном пятиминутном
префиксе с batch size 2; скрипт останавливается после устойчивого успеха либо
исчерпания матрицы/лимита 30 конфигураций.

Параметры: `--target`, `--window 145 155`, `--limit-seconds 300`, `--max-cases 30`,
`--output .lecture-cache/preprocessing-benchmark`. Результаты, тексты и тестовые SRT
сохраняются в отдельном каталоге по хэшу условий опыта. Повтор той же команды
использует сохранённые результаты. Основной SRT не изменяется. Один термин
не является оценкой общей точности лекции или WER.

Результаты первого перебора: [отчёт по предобработке](docs/preprocessing-benchmark.md).

### Контекст и декодирование ASR

Отдельный эксперимент использует проверенные исправления R001–R008 и обычное
моно без фильтров. Производственный SRT и файл исправлений не перезаписываются.

```powershell
$env:HF_HUB_OFFLINE="1" # когда все три закреплённые модели уже скачаны
uv run python -u scripts/benchmark_decoding.py "record\20260925_101716.m4a" --review "record\20260925_101716.review.md" --production-cache ".lecture-cache\24615c7efe358d62bf2a8933440ca1d85935cbb9c541940ab7e3b53357fd478a\27ce8268e5c3be49" --extended-verification
```

Сравниваются тематический контекст, словари, greedy, 2/4 луча, length penalty
и мягкое предпочтение терминов. Отдельно проверяются ложные подсказки,
90-секундные чанки, batch size 2 и повторяемость. Первые три исходных чанка
сохраняются целиком (до 05:45,920); WER считается только по проверенным фрагментам,
без повторного учёта пересекающихся исправлений.

Результаты находятся в `.lecture-cache/decoding-benchmark/<hash>/`: `metadata.json`,
`reference.json`, `summary.json`, `comparison.md`, отдельные JSON и SRT в `cases/`.
Повтор команды продолжает серию по кешу. `--prepare-only` проверяет только эталон;
`--max-cases N` позволяет сделать остановку после N конфигураций.
Числа N учитывают уже сохранённые конфигурации. Неудачные случаи тоже сохраняются;
при изменении реализации измерения необходимо изменить версию эксперимента.

`--extended-verification` дополнительно проверяет лучший безопасный словарь
с greedy и лучший вариант, восстановивший первое употребление термина,
если они улучшили исходный WER. Методика и результаты: [отчёт](docs/decoding-benchmark.md).
