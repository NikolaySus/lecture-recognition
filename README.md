# lecture-recognition

Локальный MCP-сервер для Codex: транскрибация русских лекций двумя
равноправными каналами и последующее согласование текста агентом.

Пользователь указывает аудиофайл. Сервер запускает ASR на CUDA, сохраняет
варианты A/B, исходные чанки, confidence и таймкоды. Codex читает результаты
порциями, сопоставляет расхождения, сохраняет обоснованные правки и задаёт
вопросы по неоднозначным местам. Ответы и решения переживают переподключение.
Сервер сам не вызывает LLM API; согласование выполняет агент Codex.

## Установка

Нужны Python 3.12, NVIDIA GPU, FFmpeg/ffprobe в PATH и uv.

```bash
uv sync --locked
uv sync --locked --project experiments/gigaam
uv run python -c "import torch; print(torch.cuda.is_available())"
```

Корневое окружение запускает MCP, Nemotron diarization и Qwen ForcedAligner.
Отдельное `experiments/gigaam` — окружение ASR, сохранённое под прежним именем.
Модели закреплены по ревизиям Hugging Face; первый запуск скачивает веса.
При готовом кэше ASR/диаризация/выравнивание загружаются локально без проверки сети.
Звук остаётся на локальной машине. Согласование через Codex использует текст,
переданный клиенту MCP. Проверено на Linux и CUDA; Windows-пути к isolated Python
поддержаны, но отдельный Windows-прогон пока не выполнен.

## Подключение к Codex

В репозитории есть `.codex/config.toml` с сервером `lecture_transcription` и
обнаруживаемый skill `.agents/skills/lecture-transcription`. Запускайте Codex
в этом проекте; после добавления конфигурации перезапустите сессию. Проверка:

```bash
codex mcp get lecture_transcription --json
```

Для использования сервера из других проектов можно зарегистрировать его
на уровне пользователя:

```bash
codex mcp add lecture_transcription -- "$PWD/.venv/bin/lecture-transcription-mcp" --jobs-dir "$PWD/.transcription-jobs"
```

Skill при этом нужно сделать доступным в том проекте или установить из
`src/lecture_recognition/skills/lecture-transcription`. Проектная ссылка ведёт
к этой единственной версии skill; скопированные дубликаты не нужны.

Пример запроса:

> Транскрибируй `/полный/путь/lecture.m4a`. Это лекция по анализу временных рядов.
> Сохрани речь лектора, исправь обоснованные ошибки и спроси меня о спорных местах.

## Профили и каналы

Профиль `time-series` воспроизводит исследовательский **GigaAM CTC combination**:

- GigaAM v3 CTC: `ai-sage/GigaAM-v3`, revision `15ef3b5a88da78f93134b3cb7f015c70aefa8946`;
- beam search шириной 32, предметный bias 4;
- общий для A/B исторический план чанков до 20 секунд, контекст до ±1 секунды;
- прежний алгоритм объединения перекрытий на исходной временной шкале.

Это дополнительные настройки лидера Left, применённые теперь одинаково
к обоим каналам. Для другого предмета используйте `general` или собственный
список `terms`. `terms=[]` отключает предметные термины. На stereo A — первый
канал, B — второй; при mono есть только A. Порядок не означает преимущество.
Выбор лектора по умолчанию — спикер с наибольшим временем речи; при необходимости
можно указать `speaker_id`. Одновременная речь со студентами не разделяется
на отдельные голоса.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `get_profiles` | Закреплённые настройки и словари |
| `list_jobs` | Найти сохранённое задание для аудио и продолжить вопросы |
| `start_transcription` | Создать задание, быстро вернуть ID |
| `get_status` | Этап, прогресс, спикеры, ошибка, незавершённые решения |
| `get_segments` | A/B, контекст, расхождения и сохранённые решения порциями |
| `get_raw_transcripts` | Исходные ASR-чанки с перекрытиями |
| `get_audio_clip` | WAV для прослушивания спорного места |
| `save_revision` | Выбор A/B, правка или вопрос с происхождением решения |
| `export_transcript` | TXT, Markdown, SRT и полный JSON-аудит |
| `retry_transcription` / `cancel_transcription` | Возобновить / остановить с сохранением кэша |

Большие задания работают в отдельном процессе и переживают отключение MCP.
GPU-задания в одном хранилище сериализуются. Прогресс ASR определяется по
завершённым чанкам. Повторный запрос с тем же файлом и настройками возвращает
то же задание. После ошибки используется явный retry; изменившиеся исходники
или аудио не смешиваются со старым кэшем.

Решения сохраняются атомарно с номером ревизии. Неопределённые места содержат
вопросы; финальный экспорт блокируется, пока они не разрешены. Можно явно
экспортировать черновик с альтернативами. Исходные A/B и история правок
сохраняются. SRT использует границы сегментов: слова после правок LLM не
получают выдуманных точных таймкодов. Confidence — не калиброванная вероятность
правильности текста. Если клиент не умеет прослушивать аудио, Codex даёт ссылку
на клип пользователю и не утверждает, что сам услышал запись.

По умолчанию задания находятся в `.transcription-jobs/`. Для другого места:

```bash
uv run lecture-transcription-mcp --jobs-dir /path/to/jobs
```

Если GigaAM установлен отдельно, передайте `--gigaam-python /path/to/python`
или задайте `LECTURE_GIGAAM_PYTHON`. Старый CLI `lecture-recognition` сохранён
для прежнего однотекстового Qwen-пайплайна; основной интерфейс теперь MCP.

## Проверки и исследовательская история

```bash
uv run pytest -q
```

Проверены реальный stdio MCP, JSON-схемы, повторные подключения, конфликты ревизий,
черновой/финальный экспорт, mono/stereo и защита исходного аудио. Выполнен
короткий CUDA-прогон с двумя CTC-каналами, выравниванием и сохранением решений
через MCP. Это проверка реализации, а не доказательство качества LLM-коррекции.

Исследовательские исходники и результаты в Markdown сохранены **до pivot**
в опубликованном коммите [`7fac84c`](https://github.com/NikolaySus/lecture-recognition/commit/7fac84c).
Полный старый набор можно получить в отдельном checkout этого коммита.
Аудио, модели, кэши и сгенерированные PDF в Git не входят.
Подробнее: [архитектура и статус](docs/mcp-implementation.md).
