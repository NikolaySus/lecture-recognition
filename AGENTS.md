# Настройка и работа с lecture-recognition

Это локальный MCP-сервер и skill для транскрибации русских лекций. Если пользователь
пришёл только со ссылкой на репозиторий, прочитай README и выполни установку,
проверку MCP, транскрибацию и экспорт в рамках его запроса. Согласование выполняет
сам Codex: отдельный LLM API и ключ для него не нужны.

## Установка на новую машину

- Предпочтительная проверенная платформа — Linux с работающим NVIDIA-драйвером.
  Наличие RTX само по себе не доказывает доступность CUDA. Проверены 24 ГБ VRAM;
  минимальная поддерживаемая память пока не измерена. Windows отдельно не проверен.
- Нужны Git, uv, Python 3.12, FFmpeg и ffprobe. Определи ОС и доступные утилиты;
  установи недостающие обычным для этой машины способом в пределах доступных прав.
  uv умеет установить Python: `uv python install 3.12`.
- В корне checkout выполни `uv sync --locked` и
  `uv sync --locked --project experiments/gigaam`. Не заменяй закреплённые версии
  произвольными свежими зависимостями и не используй чужое активное окружение.
- Выполни `nvidia-smi`, `ffmpeg -version`, `ffprobe -version` и проверку PyTorch
  **в обоих** окружениях по README. При недоступной CUDA сначала установи причину:
  драйвер, права/изоляция процесса, версия GPU, доступность устройства.
- Первый запуск загружает закреплённые модели из Hugging Face; нужны сеть и место
  для двух Python-окружений, весов и рабочих файлов. Не рассчитывай на кэш автора.
  Ошибки загрузки изучай по логам, не подменяй модели или ревизии автоматически.

## Подключение и полный цикл

- Запусти Codex в корне клона как доверенного проекта: там лежат
  `.codex/config.toml` и `.agents/skills/lecture-transcription`. Проверка регистрации:
  `codex mcp get lecture_transcription --json`. Проверка живого сервера в клиенте:
  `/mcp`, затем вызов `get_profiles`. Одной регистрации недостаточно.
- Если клонирование и установка выполнены в уже открытой сессии из другой папки,
  может понадобиться открыть новую сессию в клоне для загрузки MCP и skill.
  Сообщи конкретный путь запуска и причину перезапуска; не выдавай готовность
  подключения, пока инструменты недоступны. Установленный сервер можно подключить
  из другого проекта по абсолютному пути, как описано в README.
- Используй skill `lecture-transcription`. Найди существующее совместимое задание,
  затем запускай полное аудио; preview делай только по запросу пользователя.
  Читай все страницы сегментов и материалов, включая согласованные A/B.
- Пользовательские файлы, например `notes.md`, прочитай обычными файловыми
  средствами. Сохрани исходный и исправленный текст через `save_references`.
  Уточняй значимую неопределённость; выбор применения и обоснованные правки
  оставляй агенту. Сохранение материалов само по себе не меняет распознавание.
- Исходное аудио и эталоны не перезаписывай. Кэши, задания и локальный `notes.md`
  игнорируются Git. Не публикуй их вместе с исходниками.
- Полный цикл завершён, когда ASR готов, все сегменты просмотрены, решения и
  ответы сохранены, TXT/SRT/Markdown/JSON реально экспортированы и пользователь
  получил ссылки. При оставшихся вопросах сохраняй состояние и явно называй
  экспорт черновиком. Не утверждай, что прослушал аудио, если клиент этого не умеет.

## Проверка изменений исходников

После изменений runtime/MCP выполни соответствующие тесты и `uv run pytest -q`.
Для изменений skill используй доступный валидатор skill-creator. CUDA-прогон
нужен при изменениях модельного пути; обычные тесты не доказывают качество
автономного согласования или установки на чистую машину.
