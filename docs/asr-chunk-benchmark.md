# Проверка длины входа Qwen3-ASR

Проверено 25 сентября 2026 года на `record/20260925_101716.m4a`:
Windows, RTX 4060 Laptop 8 ГБ, PyTorch 2.9.1+cu128, BF16,
`Qwen/Qwen3-ASR-1.7B-hf`, ревизия `bcd2b5b7f32b480ab5790554cfa8347f246a14f3`.

## Один непрерывный вход

Каждый вход — соответствующее количество секунд от начала записи, с сохранением
пауз. Batch size 1. Скрытого дробления, CPU offload и автоматического уменьшения
чанка в тесте нет. Выполнен прогрев; время загрузки весов исключено.
В таблице — один замер на случай, не статистическое среднее.

| Длина входа | Время обработки | Пик выделенной CUDA-памяти | Результат |
|---|---:|---:|---|
| 30 с | 3,78 с | 4,03 GiB | Успешно |
| 60 с | 6,24 с | 4,24 GiB | Успешно |
| 120 с | 15,69 с | 4,68 GiB | Успешно |
| 180 с | 24,17 с | 5,11 GiB | Успешно |
| 300 с | 53,23 с | 6,57 GiB | Успешно |
| 360 с | — | — | CUDA OOM при лимите 95% VRAM |

Все успешные случаи завершились токеном EOS, без достижения лимита генерации.
Входные признаки и количество аудиотокенов увеличивались с длительностью:
длинные входы не были незаметно обрезаны до 30 секунд. EOS сам по себе не
доказывает полноту или правильность транскрипции.

Для основной серии установлен `torch.cuda.set_per_process_memory_fraction(0.95)`.
Это ограничение выделений PyTorch, а не архитектурный предел модели.
Проверенный безопасный максимум этой серии — 5 минут; точная граница между
300 и 360 секундами не определялась, работа без запаса VRAM на 360 с не проверялась.

В предварительном тесте без ограничителя 600 секунд вызвали использование
8 306 065 408 байт dedicated GPU memory и ещё 6 725 566 464 байт shared memory
по счётчику Windows `Win32_PerfFormattedData_GPUPerformanceCounters_GPUProcessMemory`.
Этот запуск остановлен: успешной транскрипцией на 8 ГБ VRAM он не считается.
1200 секунд после этого не запускались.

## Пакетная обработка

В каждом пакете повторялось одно и то же аудио, чтобы измерить память на
одинаковой длине без влияния padding разных записей. Время относится ко всему
пакету. Реальная производительность пакета разных записей может отличаться.

| Чанк × batch size | Пик CUDA-памяти | Время пакета | Результат |
|---|---:|---:|---|
| 60 с × 2 | 4,68 GiB | 6,68 с | Успешно |
| 120 с × 2 | 5,55 GiB | 18,33 с | Успешно |
| 180 с × 2 | 6,42 GiB | 38,03 с | Успешно |
| 60 с × 4 | 5,55 GiB | 13,18 с | Успешно |
| 120 с × 4 | 6,60 GiB | 34,49 с | Успешно |
| 180 с × 4 | — | — | CUDA OOM |
| 60 с × 8 | 6,60 GiB | 17,68 с | Успешно |
| 120 с × 8 | — | — | CUDA OOM |

Лимит выделений в этой серии также 95% VRAM. Пик `max_memory_allocated` не включает
всю память драйвера и отличается от зарезервированной памяти `max_memory_reserved`;
оба значения сохранены в JSON каждого теста.

## Сравнение на одинаковых первых трёх минутах

Сравнивались непрерывные 180 секунд и разбиения того же аудио на 30, 60 и
120+60 секунд. Границы фиксированные, без поиска тишины и без перекрытий:
это контролируемый эксперимент, а не новая производственная нарезка.
Согласно сохранённой диаризации, на этом участке нет других спикеров.

| Нарезка | Суммарное время ASR | Число слов после нормализации |
|---|---:|---:|
| 6 × 30 с | 19,75 с | 212 |
| 3 × 60 с | 19,52 с | 211 |
| 120 + 60 с | 21,98 с | 211 |
| 1 × 180 с | 24,17 с | 215 |

Формулировки меняются; различия есть и внутри фраз, не только на стыках.
Длинный вход не дал очевидного ускорения на этой выборке. Проверенной ручной
расшифровки нет, поэтому WER и улучшение точности не заявляются. Количество
слов и согласованность вариантов не являются оценкой качества.

Полные тексты и измерения находятся в игнорируемой Git папке
`.lecture-cache/asr-benchmark-bounded/`. Файл `comparison.md` содержит тексты
четырёх вариантов для просмотра рядом. Результат предварительного теста с
подкачкой находится в `.lecture-cache/asr-benchmark/`.

## Вывод для пайплайна

30 секунд не являются необходимым ограничением ASR на этой машине. Практический
кандидат для следующего изменения — целевые чанки около 120 секунд и batch size 2:
по памяти есть запас, без использования предельных пяти минут.

Для этого потребуется изменить сборку интервалов речи через естественные паузы,
сохранить исключение студенческих реплик и пересмотреть нынешний предел
`max_new_tokens=1024`. В бенчмарке он увеличивается с длительностью входа.
Основной пайплайн и готовый SRT этим экспериментом не изменены.

## Воспроизведение

```powershell
uv run python scripts\benchmark_asr.py record\20260925_101716.m4a --durations 30 60 120 180 300 360
uv run python scripts\benchmark_asr.py record\20260925_101716.m4a --durations 60 120 180 --batches 2 4 8 --compare-seconds 0
```

По умолчанию используется лимит 95% VRAM. Завершённые случаи берутся из кэша;
для нового измерения задайте другой `--output`. Метаданные фиксируют хэш аудио,
версии библиотек, ревизию модели и настройки эксперимента.
