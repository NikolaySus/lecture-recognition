# Последовательность экспериментов: новые ASR и адаптация к лектору

Статус на 2026-09-29: **план; новые модели и обучение не запускались**.
Контекст, данные и перенос: [experiments-handoff.md](experiments-handoff.md).
План уточняется по результатам этапов, не является требованием запустить
полное декартово произведение всех настроек.

## Цель и общие условия

Добиться заметного улучшения точной транскрипции новых лекций того же говорящего.
Одна успешно восстановленная «квазистационарность» недостаточна. Ошибки чисел,
отрицаний, пропуски и выдуманные фразы важны отдельно от среднего WER.

Основная GPU для новых опытов — RTX 4500 Ada 24 ГиБ. Менеджер окружений — uv.
Обычное моно без фильтров; сначала прежняя диаризация и маскирование.
Модели запускать последовательно, результаты и ревизии сохранять.
Не переносить требование 60–120 с входа Qwen на другие архитектуры:
оцениваем одни и те же интервалы исходного аудио, но разрешаем поддерживаемую
моделью нарезку. В отчёте такое сравнение обозначать как «модель + нарезка».

## A. Подготовить переносимую оценку

- [ ] Выделить чтение текущей ручной разметки и оценку из Qwen-specific runner.
- [ ] Сохранить неизменяемый снимок эталона с хэшем, правила нормализации,
  исходный аудиохэш, интервалы и принадлежность к train/dev/test.
- [ ] Пересекающиеся карточки считать один раз. Не делить случайным образом
  соседние/перекрывающиеся окна между train и test.
- [ ] Сохранять raw ASR до alignment отдельно от слов с таймкодами и SRT.
  Ошибки выравнивания и текстового распознавания диагностировать раздельно.
- [ ] Поддержать результаты разных моделей через общий формат с оригинальными
  временными координатами; не требовать одного и того же aligner для всех.
- [ ] Сначала воспроизвести baseline Qwen на имеющемся эталоне. На другой GPU
  побитовое совпадение не гарантировано; сохранить фактический новый baseline.

Метрики: WER с S/D/I, CER, точность значений чисел, сохранность отрицаний,
recall и precision предметных терминов, ложные термины на контрольных участках,
пропуски/повторы, пиковая VRAM и время. Эквивалентные записи числа нормализовать
одинаково, но **124 не приравнивать к 1024**, отрицания не удалять.
В имеющемся отчёте 248 слов — три объединённых участка, статистическая база мала.

Для независимой оценки запросить/подготовить разметку 10–15 минут другой лекции
того же преподавателя. Если её нет — отделённые участки текущей записи,
с явным ограничением: перенос на будущие лекции ещё не доказан.
Нужен отдельный dev для выбора настроек и закрытый test для финальной проверки.
Включить обычную речь, сложные термины, числа, паузы и участки без терминов.

Готовность этапа: единый evaluator, воспроизведённый baseline, зафиксированные
разбиения или явно указанное отсутствие независимого test.

## B. Сравнить основания без дообучения

Приоритетный набор:

| Модель | Роль |
|---|---|
| Qwen/Qwen3-ASR-1.7B-hf | Текущий baseline; пустой контекст и прежний кандидат |
| ai-sage/GigaAM-v3, RNNT и CTC | Русская база; CTC также для акустической проверки терминов |
| openai/whisper-large-v3 | Независимая архитектура, кандидат для адаптации |
| nvidia/parakeet-tdt-0.6b-v3 | Русский поддерживается; кандидат для phrase boosting |

У GigaAM различать `rnnt`/`ctc` и `e2e_rnnt`/`e2e_ctc`: последние добавляют
пунктуацию и нормализацию. Для каждого использованного варианта фиксировать
ветку и конкретный commit; сначала простой режим, дополнительные варианты
добавлять при понятном диагностическом основании.

- [ ] Проверить загрузку и CUDA на одном коротком отрывке каждой модели.
- [ ] Запустить R001–R008 без подсказок, затем оценить новые dev-участки.
- [ ] Сохранить отдельный прослушиваемый SRT каждого кандидата.
- [ ] Классифицировать исправленные и оставшиеся ошибки; выбрать 1–2 базы
  для обучения по общему качеству и критическим ошибкам, а не одному термину.
- [ ] Проверить взаимодополняемость моделей: какие правильные слова встречаются
  только у одной. Посчитать oracle WER для согласованных по интервалам кандидатов.

Oracle WER — недостижимый автоматический «идеальный выбор» с использованием
эталона; это диагностика запаса для выбора гипотез, не результат готовой системы.
Если правильных вариантов нет, один rescoring их не создаст.

MOSS-Transcribe-preview-2B не приоритетен: этот конкретный checkpoint заявлен
как английский. Не переносить его английские benchmark-показатели на русский.

## C. Управлять декодированием до обучения

Проводить на перспективных базах, не на всех моделях автоматически.

1. **Префиксное предпочтение словарю.** Для совместимой версии NeMo проверить
   GPU-PB/TurboBias (включая TDT). Для Qwen отдельный прототип префиксного
   механизма оправдан, если Qwen остаётся конкурентоспособным.
2. **Акустическое подтверждение термина.** CTC-WS или аналогичная проверка
   по CTC log probabilities. GigaAM CTC потенциально подходит, но потребует
   интеграции токенизатора/временной сетки; готовая совместимость не установлена.
   Для transducer CTC-WS нужен дополнительный CTC-выход или отдельная CTC-модель;
   не считать его автоматически доступным у Parakeet-TDT.
3. **Альтернативы и повторное ранжирование.** Сохранить n-best, проверить oracle
   и только затем пробовать предметную языковую оценку + оценку аудио.

Ранее использованный HF `sequence_bias` полного многотокенного слова влияет
на последний токен после совпавшего префикса. Его неуспех не проверяет все
варианты раннего префиксного предпочтения. Новый механизм должен учитывать
незавершённые префиксы, чтобы не поощрять обрывки терминов.

Словарь брать из темы курса/материалов, фиксировать до test. Проверять русские
словоформы, отдельные отрицательные примеры «стационарность/нестационарность»,
посторонние слова. Не подсказывать конкретное тестовое числовое значение.
Силу предпочтения настраивать на dev; отдельно считать ложные срабатывания.

Готовность: таблица «без словаря / со словарём», примеры выигрыша и регрессий,
понятно, даёт ли метод пользу вне заранее известной ошибки.

## D. Собрать данные и дообучить

### Разметка

Предлагаемая кривая объёма обучения: **5 → 15 → 30 → 60 минут**.
Это экспериментальные ориентиры, не обещание достаточности. Начать с доступного
малого объёма для проверки обучения, но не объявлять успех по R001–R008.
Собирать точную транскрипцию реального лектора, желательно нескольких записей;
сохранить повторения, числа, отрицания и речевые особенности по единому правилу.
Редакторские пометы и (!) в разметке не должны становиться произнесённым текстом.

Помимо трудных мест нужны обычные фразы и контрольные примеры без терминов.
Приоритет ручной разметки можно выбирать по расхождениям независимых ASR,
но оценочную выборку не составлять исключительно из таких расхождений.
Автоматический SRT не считать эталоном. После обучения на текущих карточках
их качество — только train/diagnostic, не показатель обобщения.

### Режимы адаптации

- [ ] Начать с LoRA BF16; обучающие фрагменты ориентировочно 5–20 с,
  по завершённым фразам. Длину уточнить по архитектуре и памяти.
- [ ] Для выбранной базы сравнить небольшие адаптеры энкодера, декодера
  (если есть подходящая обучаемая часть) и обоих. Явно записать имена модулей
  и число обучаемых параметров; не переносить target_modules между моделями.
- [ ] Ранги 8/16 — начальные гипотезы; небольшой подбор learning rate и
  early stopping на dev. Не перебирать десятки настроек на крошечном test.
- [ ] Измерить VRAM; использовать batch 1, grad accumulation и checkpointing
  при необходимости. QLoRA — резерв экономии памяти, не обязательный способ
  повышения качества. Не обещать заранее, что любое обучение влезет в 24 ГиБ.
- [ ] Если небольшой GigaAM выигрывает, рассмотреть частичное/полное
  дообучение как отдельную ветку после проверки памяти и переобучения.
- [ ] Повторить финалистов хотя бы с тремя seed; сохранить кривые train/dev,
  лучшую эпоху, весовые файлы/адаптеры, токенизатор и воспроизводимую команду.

Официальный Qwen training recipe использует пакет `qwen-asr` и исходный
checkpoint без `-hf`. Его совместимость с текущим native Transformers
checkpoint и сохранением адаптеров проверить отдельно. Не обещать, что
адаптер одного представления модели загрузится в другое без преобразования.

## E. Совместить методы и подтвердить перенос

Для лучшей базы сравнить четыре режима на одинаковом test:

| | Без словарного декодирования | Со словарным декодированием |
|---|---|---|
| Исходные веса | baseline | только декодирование |
| Адаптированные веса | только обучение | сочетание |

Дополнительная ветка, если этап B показал взаимодополняемость: основной ASR →
расхождения со вторым ASR → повторное распознавание коротких спорных интервалов →
акустическая проверка вариантов. Оценки разных моделей не складывать без
калибровки; высокая уверенность одной модели не равна правильности.
ForcedAligner сам по себе также не доказывает правильность слова.

На достаточном количестве независимых фрагментов использовать парное сравнение
и bootstrap по фрагментам/лекциям, не по отдельным словам или перекрывающимся
окнам. Зафиксировать метрики/критерии выбора до открытия test. Не обещать
значимость по трём нынешним объединённым участкам.

Кандидат должен улучшать общий текст на новых данных, не покупать выигрыш
вставкой словаря и не ухудшать систематически числа/отрицания. Численные пороги
приемлемости согласовать/зафиксировать по новому baseline до финального test.
Окончательная приёмка включает прослушивание нового SRT пользователем.

После этого проверить полную лекцию: speaker leakage, стыки, пропуски,
таймкоды и стоимость вычислений. При необходимости отдельно проверить inference
адаптированной модели на 8 ГиБ. Обучение на 24 ГиБ не означает обязательность
такой же GPU для использования адаптера.

## F. Поздние ветки — только при понятной причине

- TTS-аугментация редких терминов с контролем ложных появлений, в дополнение
  к настоящей речи лектора. Не заменять ею всю размеченную акустику.
- Осторожное self-training по согласованным гипотезам разных моделей,
  с ручной проверкой выборки. Совпадение моделей не гарантирует истинность.
- Обучение на правильных/ошибочных альтернативах, MWER/DPO/GRPO после
  устойчивого supervised baseline. На восьми карточках это легко превратится
  в запоминание ответов; не начинать с этой ветки.
- Внешняя предметная языковая модель по материалам курса, если n-best
  показывает запас для повторного ранжирования.

Эти ветки пока предложения, не готовые интеграции и не обещанный выигрыш.

## Артефакты каждого этапа

Предлагаемые, пока не созданные каталоги результатов:
`.lecture-cache/model-benchmark/<run-id>/`,
`.lecture-cache/adaptation/<run-id>/`,
`.lecture-cache/biasing-benchmark/<run-id>/`.
Конфиги/код/отчёты хранить в репозитории, аудио/веса/тяжёлые результаты —
в игнорируемом кэше с отдельной процедурой переноса.

Каждый запуск сохраняет: команду, lock/версии, model revision, хэш аудио
и эталона, split, все границы входов, prompt/словарь, seed, decoding settings,
raw outputs, timed outputs/SRT, метрики по интервалам, VRAM, время, ошибки/OOM.
Не скрывать fallback, изменение batch/нарезки или усечение генерации.
Кэш обучения также должен зависеть от состава train, весов и конфигурации.

В конце этапа добавлять короткий Markdown-отчёт со ссылками на конкретные
SRT и таблицы; явно отделять выполненное, гипотезы и следующий шаг.

## Источники и границы выводов

Источники изучены 2026-09-29. Перед реализацией проверить актуальность API,
затем закрепить версии. Результаты публикаций не переносить численно на лектора.

- [Qwen: официальный fine-tuning](https://github.com/QwenLM/Qwen3-ASR/blob/main/finetuning/README.md)
  — исходный путь SFT на парах аудио/текст; не готовая LoRA-интеграция проекта.
- [GigaAM-v3](https://huggingface.co/ai-sage/GigaAM-v3),
  [Whisper large-v3](https://huggingface.co/openai/whisper-large-v3),
  [Parakeet v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
  — характеристики кандидатов; лидерборды не заменяют локального сравнения.
- [MOSS preview](https://huggingface.co/OpenMOSS-Team/MOSS-Transcribe-preview-2B)
  — английская специализация именно обсуждавшегося checkpoint.
- [Speaker adaptation, Interspeech 2025](https://www.isca-archive.org/interspeech_2025/vandalen25_interspeech.html)
  — свидетельство возможности адаптации по минутам речи; специальный метод
  со speaker codes, не готовый рецепт для нашего Qwen.
- [PEFT: исследование одного говорящего](https://arxiv.org/html/2609.02735v1)
  — гипотезы о выборе обучаемых частей; венгерская речь с нарушениями,
  ограниченная воспроизводимость и повторно использованная оценочная выборка.
- [HF SequenceBiasLogitsProcessor](https://huggingface.co/docs/transformers/internal/generation_utils#transformers.SequenceBiasLogitsProcessor)
  — отличие bias полного слова от раннего префиксного предпочтения.
- [TurboBias](https://arxiv.org/abs/2508.07014) и
  [NeMo Word Boosting](https://docs.nvidia.com/nemo/speech/nightly/asr/asr_customization/word_boosting.html)
  — предпочтение фразам в процессе декодирования без переобучения ASR.
- [CTC-WS](https://arxiv.org/abs/2406.07096) и
  [NeMo customization](https://docs.nvidia.com/nemo-framework/user-guide/25.04/nemotoolkit/asr/asr_language_modeling_and_customization.html)
  — поиск словарных кандидатов по CTC-вероятностям и проверка ложных срабатываний.
