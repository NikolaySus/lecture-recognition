## Задача и принятые решения

Нужна точная русская транскрипция этой и будущих лекций одного преподавателя.
Оставляем говорящего с наибольшей суммарной длительностью речи. Нужен SRT
с исходными таймкодами, без пересказа и литературной правки.

- Использовать **uv и CUDA**. Исходная машина: Windows, RTX 4060 Laptop 8 ГиБ.
  Пользователь сообщил о второй машине **RTX 4500 Ada 24 ГиБ VRAM**;
  её ОС, RAM, драйвер и доступность данных ещё нужно проверить.
- Предобработка признана пользователем пока тупиковым направлением:
  основной вход — обычное моно 16 кГц без фильтров/шумоподавления.
- Разрешено исследовать смену ASR, адаптацию на малых данных и управление
  декодированием. Не ограничиваться исправлением одного слова.
- Предметный словарь можно проверять отдельным режимом. Не передавать в
  подсказках правильные предложения и ответы/числа из тестового эталона.
- Не менять рабочую транскрипцию и пользовательскую разметку экспериментами.
  Хранить отдельные результаты и SRT с исходными временными координатами.
- Не повторять весь старый перебор без нового основания. Пользователь
  прослушал SRT выбранного кандидата и считает качество неприемлемым.

## Текущее состояние

Пайплайн: FFmpeg → Nemotron diarization → выбор лектора → замена самостоятельной
чужой речи тишиной → Qwen3-ASR-1.7B-hf → ForcedAligner → SRT.
Наложения голосов не разделяются. При смене ASR первоначально сохранить
диаризацию и маскирование, чтобы не менять всё одновременно.

Текущая нарезка Qwen: максимальный вход 120 с, минимум основной части 60 с,
контекст до 1 с с каждой стороны, поиск тихих границ. Ограничение 60 с —
решение текущего пайплайна, а не требование всех будущих моделей.

Предыдущая серия: 50 случаев, 46 успешных, 4 CUDA OOM. Контекст, greedy,
beam 2/4, length penalty, sequence bias, другая нарезка и повторные запуски.
Кандидат: greedy с коротким предметным словарём без целевого термина.
На проверенных 248 нормализованных словах: 48 → 46 ошибок,
WER 19,35% → 18,55%. Это подбор на сложных местах, **не WER всей лекции**.
Повторы при одинаковых условиях воспроизводили текст; смена контекста меняла его.

Не решены: «1024» вместо «124», второе «квазистационарности» в R008,
ошибки в обычных фразах и отрицаниях. Первый целевой термин около 02:28
иногда восстанавливался при прямой подсказке, но неустойчиво к нарезке.
Один режим со словоформами скопировал словарь в транскрипцию.

R001–R008 пользователь проверил на слух, включая соседний контекст.
Пересечения объединяются в три участка; это не восемь независимых примеров.
Все эти данные уже использованы при подборе. Они подходят для разработки
и диагностики, но не для независимой проверки адаптированной модели.

## Первый сеанс на второй машине

1. Прочитать эти документы, проверить состав перенесённых файлов и `git status`.
2. Проверить GPU, драйвер, свободные VRAM/RAM/диск, FFmpeg и uv.
3. Восстановить существующее окружение и выполнить обычные проверки:

```powershell
nvidia-smi
ffmpeg -version
uv sync --locked
uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available()); print(torch.cuda.get_device_name() if torch.cuda.is_available() else 'NO CUDA')"
uv run pytest -q
uv run ruff check src tests scripts
Get-FileHash record/20260925_101716.m4a -Algorithm SHA256
```

Команды приведены для PowerShell; на Linux проверку хэша адаптировать к shell.
Не держать `HF_HUB_OFFLINE=1` при первом скачивании новых моделей.
Текущий проект закрепляет Python 3.12, torch 2.9.1 cu128 и конкретный commit
Transformers; ревизии трёх моделей находятся в `src/lecture_recognition/models.py`.

4. Новые несовместимые зависимости (NeMo, training toolkit и др.) изолировать
   в отдельных uv-проектах со своими lock-файлами, не обновлять вслепую рабочий
   `uv.lock`. ОС второй машины неизвестна: совместимость CUDA-расширений
   проверять по выбранным версиям; Linux/WSL рассматривать при необходимости.
5. Первая реализация — этапы A–B из roadmap: переносимый набор оценки,
   адаптеры новых ASR, короткий smoke test, затем сравнение на R001–R008.
   Не начинать с обучения на автоматически распознанном тексте всей лекции.

При отсутствии новых эталонов можно реализовать инфраструктуру и сравнить
модели на старой выборке. Независимый вывод о качестве откладывается до
получения ручных исправлений; их нельзя выдумывать или заменять выходом ASR.
