# CTC Gibbs: области уверенности и переключение каналов

Отдельная серия: `.lecture-cache/gibbs-study/f7bdb853c74b4711`. Основа — GigaAM CTC combination, исторические чанки и current. Декодер, RNNT, текст эталонов и склейка не изменены. Все 18 конфигураций сохранены, включая проигравшие. Исходные ASR/transcripts/aligned каждого канала остаются рядом с итоговыми решениями.

## Конфигурации

Три области: full (старый Gibbs), core (кадры только центральной части), disagreement (различия greedy-слов двух каналов с одним соседним словом с каждой стороны, затем пересечение с core). Gibbs сохраняет старую формулу, blank не участвует, повторяющиеся CTC-токены объединяются в исходные непрерывные серии. Фильтрация кадров применяется внутри этих серий; уверенность символа — минимум оставшихся кадров, слова — минимум символов, чанка — среднее слов. Локальной оценке нужно минимум три слова на каждом канале, иначе left. Greedy-различия локализуются по token_words/times posterior-трассы, без Qwen-таймкодов; время кадров приблизительно.

Два правила: hold (нынешнее удержание канала внутри порога) и independent (правый лишь при confidence_right - confidence_left > threshold, иначе левый). Равные итоговые ASR-тексты дают left. Пороги 0, 0.02, 0.05. Ни одна функция confidence не принимает эталон.

## Воспроизводимость и кандидаты

CPU development переиспользует все исходные posterior-трассы; новых ASR-прогонов на dev нет. Проверены точное воспроизведение left 18/246 и всего score для старого Gibbs/0.02 17/246. Лучшие core/independent/t0.02 и t0.05: 16/246 = 6,50%; R004 3 → 1, остальные карточки без ухудшения против left. Они выбирают соответственно три и два правых чанка.

Кандидаты выбираются только по R001–R008: общий WER не хуже left, число критических ошибок не выше, R004 лучше left. Ранжирование: ошибки, критические ошибки, CER, число правых чанков, предпочтение independent, больший порог, имя. При полностью одинаковой последовательности каналов оставляем только один вариант; замораживаем максимум две различные последовательности. После freeze параметры не меняются по S001–S012.

## Запуск

```bash
.venv/bin/python -u scripts/benchmark_ctc_gibbs.py run --retry-failed --jobs 2
```

Можно отдельно запускать development, validation или report. --research задаёт исходную фиксированную исследовательскую серию, по умолчанию берётся channel-research/latest.json. --jobs 1/2 регулирует параллельную обработку S-фрагментов. Успешные ASR, posterior и validation-cases переиспользуются после прерывания.

Результаты защищены SHA256 кода, входных diagnostics/reference/windows и ранее зафиксированных research-модулей. Изменение кода серии создаёт новый каталог; изменение старого исследовательского кода отклоняется, чтобы не смешивать версии. frozen.json включает хэши протокола и development. validation читает текст эталона только после этих проверок, проверяет воспроизведение исторического S-контроля 60/948.

## Артефакты и ограничения

protocol.json, dev-inputs.json (оба исходных канала), development.json (18 вариантов), frozen.json, validation-cases/Sxxx.json (исходные гипотезы, выравнивания, confidence, решения и итоговые слова), validation.json, status.json, reports.json. Новые GPU-диагностики сохраняются в diagnostics серии, а ASR переиспользует общий кэш фиксированного исследования.

PDF: output/pdf/r001-r008-ctc-gibbs.pdf и после проверки output/pdf/s001-s012-ctc-gibbs.pdf. Колонки отсортированы по убыванию общего WER, лучшие ячейки выделены жирным, цвет зависит от WER. R-карточки перекрываются; общая оценка использует только три непересекающиеся группы.

S001–S012 уже просмотрены и размечены с помощью ASR-черновика. Это проверка переноса, не слепой независимый тест. Допуск кандидата к дальнейшему исследованию требует WER, ошибок чисел и отрицаний не выше left; ухудшения каждого фрагмента раскрываются. Production-допуска нет даже при успешном переносе. Для подтверждения устойчивости потребуется новый заранее выбранный набор ручных эталонов. Внешние границы S и прежние дефекты выравнивания не исправляются в этой серии.

51 профильный тест прошёл, Ruff чист. PDF разработочной таблицы отрендерен и визуально проверен.
