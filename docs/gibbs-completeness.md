# Симметричная защита полноты для CTC Gibbs

Основа: Gibbs core/independent/t0.05. Если выбранный им канал короче другого сильнее допуска, выбирается другой канал. Правило действует в обе стороны. При близкой длине остаётся Gibbs; при недостаточной confidence-поддержке остаётся прежний fallback left. Тексты не редактируются и не склеиваются между каналами.

Допуск определяется относительно более длинного текста: short < long × (1 − allowance). Проверены 0%, 2%, 5%. Буквы считаются через Unicode isalpha после NFC, без пробелов, цифр и пунктуации; слова — lexical-токены. Длина измеряется по всему сырому входному ASR-чанку, включая его контекст; confidence — по core. Pure_longer — отдельный контроль без confidence, при равенстве длины left.

Сетка из шести симметричных конфигураций и четырёх контролей зафиксирована до оценки. Все варианты показаны, по S победитель для production не выбирался. Сама идея мотивирована уже просмотренным S010; поэтому S001–S012 теперь являются разработочными данными, а не независимой проверкой. Нового ASR и дообучения нет.

Все шесть симметричных защит сохраняют «элеру» в S010: left 82 буквы / 9 слов, right 77 букв / 8 слов; сокращение по буквам 6,10%, по словам 11,11%, больше всех проверенных допусков. Это сохранение распознанного имени, а не исправление его написания на «Эйлеру».

R004: left и right имеют по 163 буквы, хотя left содержит «из стационарных», right — «нестационарных». Все буквенные защиты сохраняют полезное решение Gibbs (R004 3 → 1 ошибка). По словам left имеет 23, right 22: строгий словесный фильтр блокирует правильный вариант. Допуск 5% пропускает его, поскольку разница 4,35%.

Буквенный фильтр 2% — полезный компромисс для полноты: S удаления D 22 → 17 против обычного Core, общее число ошибок 63 → 62. Но замен больше: S 35 → 39. По сравнению с left пропусков меньше (17 против 20), общих ошибок больше (62 против 60). Словесный фильтр 5%: 61 ошибка, D18; dev 18 против Core16 и left18.

Безусловный выбор по числу букв даёт S69 ошибок и dev23; по числу слов S61/D16, но dev22 и утрачивает восстановление R004. Полнота не равна длине: ошибочные формы, повторы и лишние слова тоже увеличивают счётчик. Длина всего чанка может различаться из-за контекста, даже если оцениваемая центральная речь одинакова.

Основной контроль остаётся left: устойчивое общее улучшение не доказано. Для дальнейшего исследования полноты выделяются letters/loss2% и words/loss5%, но их независимое подтверждение требует новых эталонов. Нынешняя серия не меняет декодер, склейку или основные настройки транскрибации.

Воспроизведение: `.venv/bin/python scripts/benchmark_gibbs_completeness.py`. Источник — gibbs-study/latest.json, можно указать --source. Исходные предыдущие результаты сохранены, новая серия: `.lecture-cache/gibbs-completeness/e31616b679dfc06d`. Протокол содержит SHA256 входов и кода, решения сохраняют исходное предложение Gibbs, длины обоих текстов и причину переключения.
