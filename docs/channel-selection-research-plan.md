разбиение и склейку на фиксированном левом канале; затем заморозить их и

## Спецификация этапов

### Данные и аудит

Выбирать в каждой из 12 равных временных частей ближайшее к центру окно
60 с с ≥70% речи по замороженному VAD, без исключённых интервалов.
Границы фиксируются до оценивания. Непригодные окна заменяются до проверки
с записью причины. Первоначальный пустой шаблон заменён черновиками CTC combination по просьбе пользователя.
Ручная правка всех 12 фрагментов и их пригодность подтверждены пользователем 2026-10-06;
в рабочем эталоне все отметки `valid: yes`. Оценивание ждёт замораживания профилей.

Аудит каждого стыка хранит сырые гипотезы, выравнивания, центральные границы,
входные перекрытия, решения склейки и подозрения. Раздельно учитывать ошибки
ASR, потери/дубли склейки и артефакты выравнивания/оценки. Подозрение не равно
подтверждённой ошибке; подтверждения вносятся после прослушивания.

### Объединение и разбиение

Три варианта: текущий merge_words; владение целыми словами по midpoint
центральных областей; монотонное текстовое сопоставление соседних перекрытий
с временными якорями. Нельзя удалять настоящие повторы или читать эталон.

Разбиение: максимум входа 20/30/45 с × контекст 1/2 с × регулярные/паузы-VAD
границы. Историческая раскладка — отдельный контроль; одинаковые входы
переиспользуются. Для пауз искать последнюю допустимую паузу в последних
4 с, иначе минимум энергии. Smoke test 30/45 с на обеих моделях; ошибки
и OOM не скрываются. Финалист сравнивается на границах ±2 с.

Порядок выбора: общий WER, ошибки чисел/отрицаний, подтверждённые стыки,
CER, время. При равенстве сохранять исторический вариант. Всё сравнение
проводится на левом канале с CTC beam32/bias4 и RNNT greedy. Метод склейки
выбирается до раскладки; после выбора всё замораживается отдельно по модели.

### Диагностики и селекторы

Сохранять нормированные CTC вероятности/greedy-path и посещённые RNNT
распределения/выданные токены, временную сетку и limit_hits. Отдельный кэш
диагностики включает revision модели, PCM, конфигурацию и версию алгоритма.

Confidence: экспоненциальная Gibbs и Tsallis α=1/3. Blank остаётся в
распределении, но не участвует в агрегации выданных токенов; CTC повторные
токены объединяются. Минимум по токенам слова, затем среднее по словам.
Пустая гипотеза — недоступная оценка. CTC confidence относится к greedy,
не автоматически к beam/bias тексту.

CTC-margin считает вероятности обеих конкурирующих гипотез на обоих входах
forward-алгоритмом, без bias:
D=[logP(hL|L)-logP(hR|L)]/TL-[logP(hR|R)-logP(hL|R)]/TR.
Положительное значение поддерживает левый канал; одинаковые тексты равны.
Проверить также на гипотезах RNNT; невозможный путь — недоступный показатель.

Brouhaha — отдельное окружение, официальный checkpoint и pinned revision.
Для участка медиана SNR/C50 на кадрах speech≥0,5; минимум 1 с речи.
При блокировке модели остальные диагностики продолжаются, подмены нет.

Пороги: confidence 0/0,02/0,05; SNR/C50 0/3/6 dB; margin 0/0,01/0,05.
Начальный канал левый, при малом преимуществе удерживать предыдущий,
при недоступности обоих fallback left. Выбор готового текста целого чанка,
затем замороженная склейка. Один hybrid — два из трёх голосов Tsallis,
C50 и margin с их лучшими dev-порогами; иначе удержание.

Кандидат выбирается по dev WER, ошибкам чисел/отрицаний, CER, большему
порогу. После freeze test не влияет на решения. Oracle L/R по группе или
фрагменту только диагностический, не рабочий селектор.

### Проверка и интеграция

S001–S012: историческое разбиение left, новое left/right, новый селектор.
Показать WER/CER/S-D-I, числа/отрицания, победы и потери фрагментов,
точность ранжирования неравных L/R, потери относительно oracle,
переключения и стоимость. Общий WER — сумма ошибок / сумма слов.

Допуск: WER строго лучше исторического left, ошибки чисел/отрицаний
не выросли, нет неразобранных подтверждённых ошибок склейки. Польза
селектора требует выигрыша также против нового разбиения left.
Ухудшения отдельных фрагментов допускаются и показываются. Не подбирать
замену по test. Если прошла только нарезка, экспортировать профиль left.

CLI: prepare → audit → chunk-study → diagnose → develop → freeze →
validate → report → export; progress и retry-failed. Профиль содержит
модель, раскладку, склейку, селектор, порог, версии и результаты допуска.
Новая транскрибация принимает model/selector-config и пишет SRT/JSON,
журнал решений; эталон не передаётся worker или селектору.

## Проверки

Реальные повторы, составные единицы, смещённые копии, слова на границах,
пустые чанки, противоречивые таймкоды, отсутствие дыр в центральных областях.
Confidence/blank/CTC forward на перебираемых примерах; временная сетка
Brouhaha; пороги/удержание/перестановка каналов; кэш и возобновление.
Изменение test-эталона не меняет гипотезы. Старое декодирование сохраняется.
PDF проверяется извлечением текста и визуальным рендером.

## Команды и фактическая проверка реализации

```bash
# Весь разработочный цикл; остановка при незавершённом этапе
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python scripts/benchmark_channel_research.py run-development --retry-failed
# Не запускать второй процесс параллельно с текущей серией
.venv/bin/python scripts/benchmark_channel_research.py progress
# Изолированная среда и публичный checkpoint Brouhaha
uv sync --locked --project experiments/brouhaha
.venv/bin/python scripts/setup_brouhaha.py
# После снятия блокировки Brouhaha, при уже готовых раскладках:
.venv/bin/python scripts/benchmark_channel_research.py diagnose --retry-failed
.venv/bin/python scripts/benchmark_channel_research.py develop
.venv/bin/python scripts/benchmark_channel_research.py freeze
# После ручного эталона и проверки стыков:
.venv/bin/python scripts/benchmark_channel_research.py validate --retry-failed
.venv/bin/python scripts/benchmark_channel_research.py report
.venv/bin/python scripts/benchmark_channel_research.py export
# Новая запись: только допущенный профиль
.venv/bin/python scripts/transcribe_gigaam_channels.py recording.m4a --model gigaam-rnnt --selector-config output/channel-profiles/gigaam-rnnt.json --output output/new-lecture
```

Текущая серия использует уже кэшированные pinned модели в offline режиме;
это исключает зависание на сетевой проверке метаданных HF. Скачивание Brouhaha отдельно.

Лог текущей серии: `.lecture-cache/channel-research/development.log`;
PID — `.lecture-cache/channel-research/development.pid` и `status.json`.
Текущий каталог всегда указан в `.lecture-cache/channel-research/latest.json`.

Непригодный фрагмент до freeze заменяется командой `replace-test --test-id Sxxx --reason "причина"`.
Она выбирает следующее подходящее окно в той же временной части, сохраняет
предыдущую секцию эталона, обновляет WAV и сбрасывает только эту транскрипцию.
После freeze требуется новая серия; уже проверенные test результаты не используются для подбора.

`seam-review.json` содержит подтверждения с model/merger/layout/index/type/evidence,
флагом unresolved и review_complete. Подозрения находятся в `audit.json`/`audit.md`;
после тестового прогона добавляются `test-seams/<model>/Sxxx.json`.
Даже при улучшении WER экспорт остаётся закрыт до завершения этой проверки.
